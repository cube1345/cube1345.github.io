灵枢 Agent Mesh：多 Agent 协作家庭智能助手

项目定位：让 AI Agent 不再只是「生成固件」，而是直接打通到硬件本体的操作链路。以 ESP32-S3 为核心，把轻量级 LLM Agent Runtime 落到 MCU 上，再用 MQTT Mesh 将多个节点组织成分布式协作网格；Raspberry Pi 作为边缘 AI 网关，承担本地模型部署与隐私数据的本地处理。

本项目有专门的连载文章：基于 MCU 的 Agent（一）、（二）、（三）。

四节点分工

  • Coordinator（调度者）：接入移动端、网页端、CLI 等多个渠道，理解用户意图并做任务分发，管理全局 Memory 与 Skills，处理上下文的压缩与隔离。
  • Sensor（感知者）：接入 AHT20、SGP30、BH1750/GY-30 等环境传感器，数据在节点内短暂缓存并定时发布；内部完成 EWMA 平滑滤波与异常值识别，命中条件时触发 Lua 脚本做紧急上报。
  • Control（执行者）：承接 TTS/STT 语音链路与各类硬件控制模块，执行前二次校验 Schema、TTL 及各项参数，并保留紧急停止能力。
  • Guardian（审查者）：对每条跨节点命令执行 policy_check，校验角色与 action 绑定、Capability Contract、args hash、nonce 与重放风险；高风险请求进入风险评分与人工审批队列，并通过订阅节点状态维护看门狗。

端侧 Agent Runtime

基于 ESP-IDF + FreeRTOS 实现 ReAct 风格 agent_loop，支持 Tool Calling/Registry、受限 SubAgent（spawn_subagent）、SPIFFS 持久化的 Memory/Session/Skills、上下文缓存与串口 CLI 调试。可视化侧用 ESP32-P4 + LVGL 构建统一终端，Web 端基于 React + TypeScript 做个性化偏好后台。

通信与安全

MQTT Mesh 按 node/role topic 组织，命令走结构化 schema + HMAC 签名 + nonce 防重放，配合角色白名单与 tool sandbox 约束 AI 对硬件的操作边界；tool_call、policy_decision、telemetry、mesh command 等全链路事件统一转为时间线事件流，可在 Web 端、Android 端与 ESP32-P4 上回放推理、通信与执行过程。

成果

完成轻量级 Agent 在 MCU 端的落地验证，并在此基础上构建四节点协作的 Agent Mesh；整套核心控制链路运行在成本不足百元的 ESP32-S3 上。

技术栈

ESP-IDF · FreeRTOS · MQTT Mesh · ReAct / Tool Calling · Lua · LVGL · React + TypeScript · ESP32-P4/C6 · Raspberry Pi
